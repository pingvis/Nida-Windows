# Nida for Windows 0.9.8

0.9.8 brings native microphone echo cancellation to Windows, adds NVIDIA encoding to the main REC button, and integrates upstream's work on smoother rendering and background startup. The focus is keeping the show responsive while files, devices and encoders get ready.

## Echo cancellation for calls in the room

A remote guest playing through the room's speakers can come back through your microphones and be sent straight back to the call. Windows x64 now has native **WebRTC AEC3 echo cancellation** to help remove that return path.

- Open the call bus's settings and use **Remove the echo of:** to select the bus feeding the room's speakers.
- Each microphone sent to the call bus gets its own canceller. Other buses keep the microphone's original sound.
- Echo removal works alongside the microphone's gate, EQ and compressor, with per-microphone echo information in the bus settings.
- Changes to echo removal and routing fade between states to avoid clicks.

The reference is audio played through Nida's selected room bus. Echo cancellation currently applies to the normal mixer path; **Live buses do not support it**.

## NVIDIA recording from the main REC button

The top-bar **REC** window can now use **NVIDIA NVENC** for H.264 and HEVC recordings on supported NVIDIA GPUs.

- Choose **Encoder → NVIDIA NVENC** in the recording window. CPU encoding remains the default; ProRes continues to use software encoding.
- Nida checks that the driver can actually encode before using it. The recording window shows the encoder the file is really using, including the reason for a CPU fallback.
- If NVIDIA encoding fails during a take, recording recovery continues in a new file on CPU. The next take tries the saved NVIDIA preference again.
- Recovery files keep the current take's name. A name edited during recording applies to the next take.
- Stopping a recording with a silence-only audio input no longer waits for the audio finalization timeout.

This accelerates encoding while retaining the existing audio routing, file frame rate and crash-recovery behavior.

## Less work for the renderer

- Simple cropped, positioned or scaled layers can draw directly into their input, avoiding an intermediate copy.
- Compatible **Normal**, **Add** and **Screen** layers are combined into fewer rendering passes.
- The resolution control can suggest a smaller show size when it is sufficient for the outputs with fixed dimensions. Changing the size remains your choice.
- **LED screens keep their intended section of the picture when the show's render size changes.**

## More work happens in the background

- Recording and streaming encoders start alongside the show, with a visible starting state while they get ready.
- Clips and pictures added over the API open in the background.
- File lookups, log writing and more media/device cleanup work are kept off the show thread, reducing interruptions from slow disks, unavailable files and devices that take time to close.
- Windows file logging retains its rotating logs and panic reporting through the new background logging queue.
- Background media and encoder startup stay tracked through shutdown, including a recording cancelled while it is still starting.

## Audio refinements

Microphone input timing is more consistent when a device reopens, and the normal mixer settles more smoothly after a Live bus closes. The Windows fork's input and bus EQ remain available alongside the upstream audio processing changes.
