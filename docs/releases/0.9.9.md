# Nida for Windows 0.9.9

0.9.9 adds animated frames for cameras, slides and other layers, expands the Broadcast backgrounds to 27 looks, and reduces rendering work when pictures stay unchanged. It also brings NDI output fixes, more flexible capture controls, presentation improvements and clearer Windows streaming errors.

## Put a layer in a frame

Choose **Input Settings → select a layer → Position → Frame** to add one of **12 frames**, including HUD frame, Neon ring, Electric, Silver deco and Stream overlay.

- Frames follow the visible part of the picture, including what Crop keeps and a cropped picture repeated from another input. A completely clear layer has no visible frame.
- Move or resize the layer and the picture and frame move together. Layout templates can place framed layers just like other layers.
- Put the **Picture inside the frame** to keep its outline off the edges of a slide, or draw the frame over the picture's edge.
- Choose a window shape matching the picture, 16:9, 4:3, square or portrait. **Fill the frame** fills that shape; **Size** scales the framed picture within the layer.
- Customize frame and light colours, thickness, glow, backing and speed. Animation choices include travelling lights, breathing and Still; Speed 0 freezes the animation.
- Switching frame styles keeps the settings you changed where the new style has matching controls.

New frames load in the background on the Windows fork. The API exposes frame selection through `SetLayerFrame` and lists available styles in `GET /api/state/registry`.

## Seventeen more Broadcast backgrounds

There are now **27 Broadcast backgrounds**, with 17 additions across the existing moods:

- **Tech:** Plexus wave, Dot horizon, Dot globe, Light fibres and Rising tiles.
- **Cyber:** Grid floor, Radar sweep and Hex tunnel.
- **Warm:** Embers, Light rays and Stage curtain.
- **Calm:** Caustics, Flowing lines, Far ridges and Ink in water.
- **Colours:** Colour fields and Halftone.

They share the familiar palette, custom-colour and speed controls. **Calm centre** now softens a broad, rounded area in the middle and blends gradually toward the edges, leaving a quieter space behind a speaker or slide. It replaces the earlier lower-third band.

## Less rendering when the picture stays the same

- Still text, lower thirds, paused clips and other unchanged input pictures can reuse their previous render until something changes.
- Clips can keep their picture between decoded frames, and screen/window layers between captured frames.
- Empty inputs can stay clear without being drawn again every frame.
- When Main is simply one full-level input with no additional processing required, it can use that input's picture directly.
- Compatible Main layers are combined into fewer rendering passes, and several soft Broadcast backgrounds use a lighter rendering path.

These changes reduce repeated work in shows with static graphics, slides and lower-frame-rate sources. Animated effects and changing pictures still need to be rendered.

## NDI output improvements

- Video conversion and transmission run on a dedicated sender thread, reducing the work NDI output puts on the show thread.
- If sending falls behind, the newest waiting picture replaces an older one rather than building up a queue of stale pictures.
- **10-bit NDI output now matches the brightness curve of the other outputs**, fixing darker shadows.
- Removing an NDI output or changing its sender name removes the old source from network discovery. Stopping an output keeps its source available but silent.

## Capture and presentation controls

- Pick a different screen or window from an existing capture input's settings, with **Refresh** to rescan available targets. The layer keeps its effects and place in the show.
- Capture sizing better accounts for how large the picture is actually drawn, including fill and zoom, and improves pixel alignment when placing pictures.
- Inputs that share one capture use that capture's rate, crop and cursor settings consistently.
- Missing capture targets keep their saved input names and settings so they can be reassigned.
- **End talk** stops the current talk without removing it from the running order. PowerPoint's show ends, and Nida stops opening other talks ahead for playback until you start one again. An ended talk is not restarted when the saved show opens.

PDF-based next-slide previews and automatic PDF slide pictures still require macOS's PDF renderer. Those features are **not available on Windows**; Windows PowerPoint automation continues through the native COM integration.

## Clearer Windows streaming failures

Windows FFmpeg socket errors now produce useful messages for connection timeouts, refused connections and closed connections, instead of falling back to “The sender stopped.”

The Windows reconnect checks now cover a server returning after a failed connection and a network change interrupting the retry pause. Both pass, including repeated verification that a network change starts a new attempt within one second of being reported to the sender. Existing connection timeouts and retry intervals are unchanged.

## Smaller fixes

- Correct ordering of multi-pass frame effects keeps them working from the current picture rather than stale pass results.
- Repeated log messages are reduced during long-running shows.
- Late-frame diagnostics include what the preceding frame was doing, making performance problems easier to investigate.

---

NVIDIA recording from the main REC button and native Windows echo cancellation shipped in 0.9.8 and remain available here. Users upgrading from 0.9.7 can also read the [0.9.8 release notes](https://github.com/pingvis/Nida-Windows/releases/tag/0.9.8).

This is the **Windows x64 fork**, incorporating upstream Nida 0.9.9. NDI requires its runtime to be installed separately.
